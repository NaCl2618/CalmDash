# 기능 명세서: 화면 켜짐 유지 (Screen Wake Lock)

**기능 브랜치**: `001-screen-wake-lock`
**생성일**: 2026-01-23
**상태**: 초안
**입력**: 사용자 설명: "안드로이드 기기 및 기타 플랫폼에서 자동 화면 타임아웃을 방지하기 위한 Screen Wake Lock 기능"

## 사용자 시나리오 및 테스팅 *(필수)*

### 사용자 스토리 1 - 대시보드 조회를 위한 화면 켜짐 유지 활성화 (우선순위: P1)

사용자는 안드로이드 기기(또는 태블릿/데스크톱)에서 CalmDash를 항상 보이는 대시보드로 사용하고 싶어하며, 기기의 타임아웃 설정으로 인해 화면이 자동으로 꺼지지 않기를 원합니다. 생산성 정보를 보면서 화면을 계속 활성 상태로 유지할 방법이 필요합니다.

**우선순위 이유**: 이것이 이 기능의 핵심 가치 제안입니다. 화면을 켜진 상태로 유지하는 기능이 없으면 대시보드가 상시 켜짐 시나리오에서 사용할 수 없게 되며, 이는 E-Ink 디스플레이 및 전용 대시보드 설정의 주요 사용 사례입니다.

**독립 테스트**: 앱의 설정 패널에서 "화면 켜짐 유지" 설정을 활성화하고, 기기를 유휴 상태로 두고, 기기의 일반 타임아웃 시간을 넘어서도 화면이 활성 상태로 유지되는지 확인하여 완전히 테스트할 수 있습니다. 대시보드 사용 사례에 즉각적인 가치를 제공합니다.

**수락 시나리오**:

1. **Given** 사용자가 지원되는 브라우저(Chrome 84+, Firefox 126+, Safari 16.6+)에서 CalmDash를 열었을 때, **When** 설정으로 이동하여 "화면 켜짐 유지"를 활성화하면, **Then** 앱이 보이는 동안 화면이 무한정 활성 상태로 유지됨
2. **Given** "화면 켜짐 유지" 기능이 활성화되어 있을 때, **When** 사용자가 다른 탭이나 앱으로 전환하면, **Then** wake lock이 해제되고 기기가 일반 타임아웃 동작으로 돌아감
3. **Given** "화면 켜짐 유지" 기능이 활성화되어 있을 때, **When** 사용자가 CalmDash 탭으로 다시 전환하면, **Then** wake lock이 자동으로 다시 획득되고 화면이 다시 켜진 상태로 유지됨
4. **Given** 사용자가 "화면 켜짐 유지"를 활성화했을 때, **When** 브라우저를 닫거나 다른 곳으로 이동하면, **Then** 설정이 유지되고 다음 세션에서 기억됨

---

### 사용자 스토리 2 - 지원되지 않는 환경의 우아한 처리 (우선순위: P2)

사용자가 Screen Wake Lock API를 지원하지 않는 환경(구형 브라우저, HTTPS 대신 HTTP, 또는 지원되지 않는 플랫폼)에서 "화면 켜짐 유지" 기능을 활성화하려고 시도합니다. 해당 기능을 사용할 수 없는 이유에 대한 명확한 피드백이 필요합니다.

**우선순위 이유**: 사용자 경험과 혼란 방지에 필수적이지만, 지원되는 환경에서 작동하는 핵심 기능보다는 부차적입니다.

**독립 테스트**: HTTP(HTTPS가 아닌)에서 CalmDash에 접근하거나 구형 브라우저 버전에서 설정을 활성화하려고 시도하고, 기능을 사용할 수 없는 이유를 설명하는 적절한 피드백이 표시되는지 확인하여 테스트할 수 있습니다.

**수락 시나리오**:

1. **Given** 사용자가 HTTP(HTTPS가 아닌)를 통해 CalmDash에 접근했을 때, **When** 설정 패널을 보면, **Then** "화면 켜짐 유지"에 HTTPS가 필요함을 나타내는 안내 텍스트를 봄
2. **Given** 사용자가 Wake Lock API를 지원하지 않는 브라우저를 사용 중일 때, **When** 기능을 활성화하려고 시도하면, **Then** 시스템이 유익한 오류 메시지를 로그에 기록하고 토글이 비활성화 상태로 돌아감
3. **Given** Wake Lock 요청이 어떤 이유로든 실패했을 때, **When** 오류가 발생하면, **Then** 사용자는 방해받지 않고 앱이 표준 타임아웃 동작으로 정상적으로 계속 작동함

---

### 사용자 스토리 3 - Wake Lock 상태의 시각적 피드백 (우선순위: P3)

사용자가 "화면 켜짐 유지"를 활성화하고, 특히 다른 탭에서 앱으로 돌아온 후나 브라우저를 재시작한 후 기능이 현재 활성화되어 있는지 한눈에 알고 싶어합니다.

**우선순위 이유**: 사용자 신뢰도를 향상시키는 좋은 개선사항이지만 기본 기능에 중요하지 않습니다. 이 기능은 백그라운드에서 투명하게 작동합니다.

**독립 테스트**: 기능을 켜고 끄며 설정 UI를 관찰하여 현재 상태가 명확하게 표시되는지 확인하여 테스트할 수 있습니다.

**수락 시나리오**:

1. **Given** 사용자가 "화면 켜짐 유지"를 활성화했을 때, **When** 설정 패널을 열면, **Then** 토글 스위치가 활성화된 상태를 표시함
2. **Given** Wake Lock이 활발하게 화면 타임아웃을 방지하고 있을 때, **When** 사용자가 앱을 보면, **Then** 설정이 활성 상태를 정확하게 반영함

### 엣지 케이스

- 사용자의 기기 배터리가 매우 낮을 때 어떻게 됩니까? (시스템이 Wake Lock을 재정의할 수 있음)
- 브라우저 탭이 백그라운드 vs 포어그라운드일 때 시스템이 Wake Lock을 어떻게 처리합니까?
- 사용자가 Wake Lock을 활성화한 후 브라우저가 충돌하거나 연결이 끊어지면 어떻게 됩니까?
- 공격적인 배터리 최적화가 있는 플랫폼(예: 배터리 절약 모드가 있는 Android)에서 기능이 어떻게 동작합니까?
- 사용자가 Wake Lock 권한을 거부하면 어떻게 됩니까? (브라우저가 프롬프트를 표시하는 경우)

## 요구사항 *(필수)*

### 기능적 요구사항

- **FR-001**: 시스템은 설정 패널에서 "화면 켜짐 유지" 기능을 활성화/비활성화할 수 있는 사용자 접근 가능한 토글 컨트롤을 제공해야 함
- **FR-002**: 시스템은 Screen Wake Lock API를 사용하기 전에 브라우저 지원 여부를 감지해야 함
- **FR-003**: 시스템은 기능이 활성화되고 페이지가 보일 때 화면 wake lock을 요청해야 함
- **FR-004**: 시스템은 페이지가 숨겨질 때(탭 전환, 최소화 등) wake lock을 자동으로 해제해야 함
- **FR-005**: 시스템은 페이지가 다시 보일 때(설정이 여전히 활성화된 경우) wake lock을 자동으로 다시 획득해야 함
- **FR-006**: 시스템은 LocalStorage를 사용하여 브라우저 세션 간에 사용자의 wake lock 기본 설정을 유지해야 함
- **FR-007**: 시스템은 저장된 사용자 기본 설정을 기반으로 페이지 로드 시 wake lock 상태를 초기화해야 함
- **FR-008**: 시스템은 기능에 HTTPS 및 브라우저 지원이 필요함을 나타내는 안내 도움말 텍스트를 제공해야 함
- **FR-009**: 시스템은 사용자 경험을 방해하지 않고 wake lock 실패를 우아하게 처리해야 함
- **FR-010**: 시스템은 디버깅 목적으로 wake lock 오류를 콘솔에 로그해야 함
- **FR-011**: 시스템은 Chrome 84+, Firefox 126+ 또는 Opera 73+를 실행하는 Android 기기에서 작동해야 함
- **FR-012**: 시스템은 Safari 16.6+를 실행하는 iOS/iPadOS 기기에서 작동해야 함
- **FR-013**: 시스템은 데스크톱 브라우저(Chrome 85+, Edge 90+, Firefox 126+, Safari 16.6+)에서 작동해야 함

### 주요 엔티티

- **Wake Lock 설정**: LocalStorage의 `settings.screenWakeLock` 속성 아래에 저장된 불린 사용자 기본 설정 (기본값: false)
- **Wake Lock Sentinel**: 애플리케이션 상태에서 참조로 보유된 활성 화면 wake lock을 나타내는 브라우저 관리 객체

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 수동 상호작용 없이 CalmDash 대시보드를 보는 동안 화면을 무한정 활성 상태로 유지할 수 있음
- **SC-002**: wake lock 기본 설정이 브라우저 세션 간에 100% 신뢰성으로 유지됨 (LocalStorage에 저장)
- **SC-003**: 사용자가 탭을 전환하거나 브라우저를 최소화할 때 wake lock이 1초 이내에 자동으로 해제됨
- **SC-004**: 사용자가 CalmDash 탭으로 돌아올 때(활성화된 경우) wake lock이 1초 이내에 자동으로 다시 획득됨
- **SC-005**: 기능이 지정된 최소 브라우저 버전으로 모든 지원되는 플랫폼(Android, iOS/iPadOS, 데스크톱)에서 올바르게 작동함
- **SC-006**: 기능이 지원되지 않는 브라우저에서 오류를 일으키거나 다른 기능을 손상시키지 않고 우아하게 저하됨
- **SC-007**: 사용자가 설정 패널의 도움말 텍스트를 통해 HTTPS 요구사항 및 브라우저 지원에 대한 명확한 피드백을 받음

## 가정 사항 *(선택)*

- 사용자는 "화면 켜짐 유지"가 모바일 기기의 배터리 수명에 영향을 미칠 것임을 이해함
- 사용자는 Wake Lock API를 지원하는 최신 브라우저(최근 2-3년 내에 출시)에 액세스할 수 있음
- CalmDash는 프로덕션 환경에서 HTTPS를 통해 제공됨
- Wake Lock API의 브라우저 구현은 표준 사양을 따름
- 기기 수준 배터리 최적화 설정이 극단적인 경우(배터리 부족, 공격적인 절전) 앱 수준 wake lock을 재정의할 수 있음

## 의존성 *(선택)*

- Screen Wake Lock API에 대한 브라우저 지원 (W3C 사양)
- HTTPS 연결 (Wake Lock에 대한 브라우저 보안 정책에 필요)
- 탭 가시성 변경을 감지하기 위한 Page Visibility API
- 사용자 기본 설정을 유지하기 위한 LocalStorage

## 범위 외 *(선택)*

- 사용자 정의 wake lock 기간 제한 (wake lock은 탭이 숨겨지거나 사용자가 비활성화할 때까지 활성 상태로 유지됨)
- 배터리 소비 모니터링 또는 경고
- 네이티브 API 지원 없이 브라우저를 위한 대체 wake lock 방법
- 배터리 수준에 따른 wake lock 자동 비활성화
- 섹션별 wake lock 컨트롤 (기능이 전체 대시보드에 적용됨)
- 데스크톱 전용 keep-awake 메커니즘 (브라우저 수준이 아닌 시스템 수준)

**입력**: `/specs/001-screen-wake-lock/`의 설계 문서
**전제 조건**: plan.md ✅, spec.md ✅, research.md ✅, data-model.md ✅, quickstart.md ✅

**테스트**: 자동화된 테스트 없음 - 수동 브라우저 테스트만 수행 (프로젝트 표준에 따름)

## 의존성 및 실행 순서

### 단계별 의존성

- **설정 (1단계)**: 의존성 없음 - 즉시 시작 가능
- **기반 (2단계)**: 설정 검증 완료에 의존
- **사용자 스토리 (3-5단계)**: 모두 기반 단계 검증에 의존
  - 사용자 스토리는 병렬로 진행 가능 (다른 테스터/기기)
  - 또는 우선순위 순으로 순차적으로 진행 (P1 → P2 → P3)
- **다듬기 (6단계)**: 모든 사용자 스토리 검증 완료에 의존

### 사용자 스토리별 의존성

- **사용자 스토리 1 (P1)**: 기반 (2단계) 후 시작 가능 - 다른 스토리에 의존성 없음
- **사용자 스토리 2 (P2)**: 기반 (2단계) 후 시작 가능 - US1과 독립적
- **사용자 스토리 3 (P3)**: 기반 (2단계) 후 시작 가능 - US1 및 US2와 독립적

**독립성 검증**: 각 사용자 스토리는 완전히 독립적으로 테스트 가능합니다. US1을 먼저 검증하지 않고도 US2를 검증할 수 있습니다.

### 각 사용자 스토리 내에서

- 수동 테스트는 병렬로 실행 가능 (다른 브라우저/기기)
- 문서화 작업은 병렬로 실행 가능
- 구현 개선 (있는 경우)은 문서화 전에 테스트되어야 함

### 병렬 기회

- **1단계**: [P]로 표시된 모든 4개 작업을 병렬로 실행 가능
- **2단계**: T005-T009 작업은 순차적으로 실행 (관련 기능 검증)
- **3단계 (US1)**: [P]로 표시된 모든 6개 수동 테스트(T010-T015)를 다른 기기에서 병렬로 실행 가능
- **4단계 (US2)**: [P]로 표시된 모든 4개 수동 테스트(T019-T022)를 병렬로 실행 가능
- **5단계 (US3)**: [P]로 표시된 모든 3개 수동 테스트(T027-T029)를 병렬로 실행 가능
- **6단계 문서화**: [P]로 표시된 T033-T036을 병렬로 실행 가능
- **6단계 교차 브라우저**: [P]로 표시된 T041-T045를 다른 기기에서 병렬로 실행 가능
- **6단계 엣지 케이스**: [P]로 표시된 T055-T058를 다른 기기에서 병렬로 실행 가능

## 참고 사항

### 기능 상태
- ✅ 핵심 구현 완료 (커밋 `0ac01a5`)
- ✅ 세 가지 깨우기 잠금 함수 모두 구현됨
- ✅ 설정 토글 구현됨
- ✅ 페이지 가시성 처리 구현됨
- 🔄 문서화 완료 필요
- 🔄 교차 브라우저 테스트 필요
- 🔄 README 업데이트 필요

### 테스트 접근 방식
- 자동화된 테스트 없음 (프로젝트에 테스트 프레임워크 없음)
- 플랫폼 간 수동 브라우저 테스트
- 실제 사용 시나리오에 중점
- 가능한 경우 실제 기기에서 테스트

### 문서화 우선순위
- README.md 업데이트 (높은 우선순위)
- 브라우저 호환성 매트릭스 (높은 우선순위)
- 문제 해결 가이드 (중간 우선순위)
- 스크린샷/시각적 보조 (중간 우선순위)
- 성능 메트릭스 (낮은 우선순위)

### 향후 개선 (범위 밖)
- 자동화된 브라우저 테스트 (테스트 인프라 필요)
- 배터리 소비 모니터링
- 깨우기 잠금이 활성화될 때 시각적 표시기
- 깨우기 잠금 지속 시간 제한
- 지원되지 않는 브라우저를 위한 대체 구현

## 기여자를 위한 빠른 시작

**기존 구현을 검증하려면**:

1. 1단계 (설정 및 검증) 시작 - 코드 존재 확인
2. 2단계 (기반) 진행 - 핵심 인프라 검증
3. 사용 가능한 기기에 따라 사용자 스토리 선택:
   - Android 기기가 있음? → 사용자 스토리 1 (P1)
   - HTTP에서 테스트 중? → 사용자 스토리 2 (P2)
   - UI만 확인 중? → 사용자 스토리 3 (P3)
4. 테스트 결과 문서화
5. README.md에 결과 업데이트
6. 커밋하고 다음 스토리 또는 6단계 작업으로 이동

**문서화를 추가하려면**:

1. 3-6단계에서 문서화 작업 선택
2. app/js/main.js 및 app/index.html의 기존 구현 검토
3. 실제 코드를 기반으로 문서화 작성
4. 필요한 경우 수동 테스트로 정확성 확인
5. 문서화 업데이트 커밋

**교차 브라우저 테스트를 실행하려면**:

1. 6단계 교차 브라우저 작업에서 브라우저 선택
2. 3단계 (US1)의 테스트 절차 따르기
3. 브라우저 호환성 매트릭스에 결과 기록
4. 테스트 결과 문서화 커밋
